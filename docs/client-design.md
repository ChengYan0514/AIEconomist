# AI Economist 客户端架构与前端设计方案

本文定义 AI Economist 客户端科研工作台的整体架构、权限路由边界、前端视觉与交互设计方案，以及与后端契约（[openapi-client.yaml](openapi-client.yaml)）的映射关系。架构决策见 [ADR 0005](adr/0005-client-host-and-external-capability-engines.md)，领域术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 1. 整体架构与边界

```text
Browser (frontend/ 单应用：管理端 /* + 客户端 /client/*)
    │  同源 Cookie (PAPERFLOW_SESSION) + CSRF
    ▼
Java Spring Boot 宿主 (backend/ :8095)
    ├── 管理端业务包 (/api/*)
    └── 客户端宿主包 com.paperflow.client.* (/api/client/*)
          ├── 模块能力目录 (/modules)
          ├── 公共语料只读服务 (/journals -> v2_paper_read + sources)
          ├── 本地书目元数据补全 (work / work_author / work_source / v2_paper)
          ├── 持久化任务历史与人工审阅重排 (v2_client_citation_task / event)
          └── 语言无关外部引擎端口
                ├── CitationEngine  ──► [stub | CitationsRetrievalSystem | 未来 TS Agent (standard-v1)]
                ├── (预留) QaEngine ──► 未来独立学科知识问答项目
                └── (预留) WritingEngine ──► 未来独立论文写作智能体项目
```

### 角色与双端入口规则

- **新增权限**：`Permission.Group.CLIENT` 下设 `CLIENT_ACCESS`（「访问客户端科研工作台」）。
- **新增内置角色**：`RESEARCHER`（**研究者**），仅持有 `CLIENT_ACCESS`，无法进入数据管理端页面与管理端 API。
- **既有内置角色**：`SYSTEM_ADMIN`、`DATA_MAINTAINER`、`READ_ONLY` 默认附带 `CLIENT_ACCESS`，登录后可在双端间一键切换。
- **登录页（`frontend/src/login.tsx`）**：
  - 保留「管理端」「客户端」双标签页，两个标签均提供真实登录表单（调用同一 `POST /api/session`）。
  - 从「管理端」登录默认进入 `/overview`；若账号仅有 `CLIENT_ACCESS` 无任何管理端权限，自动导向 `/client/citations`。
  - 从「客户端」登录默认进入 `/client/citations`；若账号不持有 `CLIENT_ACCESS`（例如未勾选该权限的自定义角色），给出明确无权限提示并提供前往管理端的入口。
- **路由完全隔离**：
  - 管理端所有既有路由（`/overview`、`/journals`、`/papers`、`/jobs`、`/openalex`、`/causal-*`、`/system-status`、`/users`、`/roles`、`/audit`）保持原样，不破坏现有链接和浏览器验收测试。
  - 客户端统一位于 `/client/*`：
    - `/client` → 自动导向 `/client/citations`
    - `/client/citations` 与 `/client/citations/:taskId` → **参考文献自动标注**
    - `/client/qa` → **学科知识问答**（高完成度科研交互骨架）
    - `/client/writing` → **论文写作智能体**（高完成度科研交互骨架）

## 2. 客户端视觉语言与工作台壳层

延续 AI Economist 既有的「**暖编辑学术纸张**」视觉基因（`--bg: #f7f5f0`、暖灰侧栏 `#efece5`、纯白纸面 `#ffffff`、墨黑主按钮 `#1b1e24`、深海军蓝强调 `#1e4477`、暗红品牌印记 `#a62626`、衬线标题 `Newsreader / Songti SC` + 无衬线正文），但**打破管理端密集表格风**，转为更舒展、沉浸式的三层级科研工作台：

1. **最左侧精简模块导航轨（Client Rail，宽 216px，可折叠为 64px 图标轨）**：
   - 顶部：`AI Economist` 品牌标 + 副标「科研工作台」
   - 一级模块导航（由 `GET /api/client/modules` 驱动状态角标）：
     - **参考文献自动标注**（`BookCheck` / `Quote` 图标，状态点：已就绪 / 演示模式 / 未连接）
     - **学科知识问答**（`MessageSquareText` 图标，角标「待接入」）
     - **论文写作智能体**（`PenTool` 图标，角标「待接入」）
   - 底部区：
     - 双端切换按钮（仅当账号具备至少一项管理端权限时显示：「切换至数据管理端」→ `/overview`）
     - 离线前端演示开关（仅当开发模式或后端接口尚未就绪时可一键启用契约 Mock 数据预览，默认优先连接真实 `/api/client/*`）
     - 当前用户账号菜单（修改密码 / 退出登录）
2. **模块内上下文边栏（如引文标注的「历史任务」抽屉/列表、问答的「历史会话」、写作的「文稿目录」）**：
   - 可折叠，支持快速新建、状态筛选与按时间回溯。
3. **主工作区（宽敞纸张容器，适配 ≥1280px 桌面三区协作与 ≤1024px 响应式标签页切换）**。

> 管理端侧栏底部（账号菜单上方，不影响 `.sidebar-heading` 键盘 Tab 序）同样增加「进入科研客户端」快捷入口（仅在持有 `CLIENT_ACCESS` 时显示）。

## 3. 模块一：参考文献自动标注（完整契约驱动界面）

路由：`/client/citations`（新建/空态）与 `/client/citations/:taskId`（指定任务详情/运行中/结果审阅）。

### 3.1 信息架构（3 种清晰工作态）

1. **新建与草稿输入态（Draft Studio）**
   - **左栏（历史任务列表，260px，可收起）**：
     - 顶部「新建标注任务」主按钮 + 状态筛选（全部 / 运行中 / 已完成 / 失败）。
     - 展示当前用户的历史 `CitationTaskSummary`（标题、引文样式徽标、状态圆点、陈述/已选文献数、更新时间、删除按钮）。
   - **主画布（居中舒展学术纸张卡片，max-width 860px）**：
     - 顶部条：可选「任务标题」输入 + 「填入示例段落」快捷按钮 + 字数统计（上限 20,000 字）。
     - 核心草稿区：大号衬线/清晰行高文本编辑器，支持中英文学术段落。
     - 检索策略栏（折叠/展开清晰卡片）：
       - **引文样式**分段选择器：`APA` | `IEEE` | `Chicago Author-Date` | `MLA`
       - **限定期刊**可搜索多选器（数据来自 `GET /api/client/journals`，展示期刊名与本地全文篇数，已选以可移除标签呈现；空选表示不限来源）
       - **发表年份范围**：起始年 — 结束年（前端实时校验 `yearMin <= yearMax`）
     - 底部动作栏：显示当前接入引擎状态徽标（例如「实时引擎」或「演示 Stub」）+ 主按钮「开始自动标注」。

2. **执行中进度态（Live Pipeline View）**
   - 提交 `POST /api/client/citations/tasks` 返回 `202` 后，路由切至 `/client/citations/:taskId`，立即订阅 `GET /api/client/citations/tasks/{taskId}/events`（SSE，断开时自动回退至快照轮询）。
   - **顶部阶段步进条**：`解析陈述` → `规划检索` → `向量与全文召回` → `证据强度评估` → `本地书目补全` → `引文排版`，实时百分比进度条 + 「取消任务」按钮（`POST /cancel`）。
   - **实时事件流时间线**：按顺序展示每一步详情（例如抽取了 N 条引文陈述、召回与送审块数、补全进度）；若任务失败，保留原文并提供「回到草稿修改重提」按钮。

3. **结果与人工审阅工作台（Review & Export Workbench）**
   - 桌面端采用**左-中-右三栏协作**（左历史栏可一键收起为极窄条，把 85% 宽度让给「交付正文」与「证据审阅」双栏）：
   - **中栏：交付正文与参考文献（Paper Canvas）**
     - 顶部交付工具栏：
       - **即时引文样式切换器**（`APA` / `IEEE` / `Chicago` / `MLA`，切换直接调用 `PATCH /review` 毫秒级服务端重排并持久保存）
       - **一键复制**（正文 + 参考文献）
       - **导出下拉菜单**：下载 `.txt`、`.md`、`.bib`（BibTeX）（调用 `GET /export?format=...`）
       - **基于此原文新建任务**按钮
     - **带引文正文区**：
       - 按学术稿件排版，支持高亮当前聚焦的「引文陈述」（点击右侧任一陈述自动滚动并高亮对应句段，反之点击正文内高亮陈述也自动定位右侧证据卡）。
       - 当存在 `warnings`（如某条陈述召回触顶或原始支持文献超过 5 篇）时，顶部以克制的信息条折叠展示。
     - **参考文献列表区（References）**：悬挂缩进学术样式呈现 `bibliography`，并标注总引用去重篇数。
   - **右栏：引文陈述与证据审阅抽屉（Evidence Inspector，宽 420px）**
     - 顶部汇总指标：`共 N 条引文陈述 · 已采纳 M 篇文献`；若审阅勾选有未保存改动或正在重排，显示清晰状态反馈。
     - **引文陈述手风琴列表**（对应 `statements`）：
       - 卡片头：陈述序号、文本摘要、「已选 X / 备选 Y 篇」徽标、点击联动高亮正文。
       - 展开后顶部展示精简 **证据统计条**（送审片段数、通过文献数、拒绝原因分布小提示、`召回触顶`/`送审触顶` 警示徽章）。
       - **候选参考文献清单**（全部 `referencesByStatement[statementId]`，不再把第 6 篇以后藏成无标题黑盒！）：
         - 每条文献带 **勾选框**（决定是否插入正文并计入参考文献列表），支持用户自由取消 AI 推荐或一键把备选文献换入正文，勾选变更后触发 `PATCH /review` 即时重排并落库。
         - 展示本地补全后的完整书目：标题、作者、年份、期刊名、DOI 链接、「本地库已收录」标记（`paperId != null`）以及支持度/置信度标签（`supportScore` / `confidence`）。
         - 可展开查看每篇文献对应的 **支持原文证据片段（`chunks`）**（含章节标题、原文引用块与 LLM 判定理由 `reason`）。

### 3.2 契约驱动前端 Mock 联调开关

在 Codex 完成后端分支合并前，前端提供独立的契约适配层 `frontend/src/client/api.ts`：
- 默认直连真实 `/api/client/*` API。
- 当接口返回 `404`（后端尚未合入）或用户在页面顶部切换「契约演示模式（Mock）」时，无缝切入严格符合 `docs/openapi-client.yaml` 的本地模拟实现（包含完整阶段进度动画、可勾选重排的真实经济学示例文献、样式切换与 `.txt`/`.md`/`.bib` 导出），确保前端设计可直接交互验收，后端合入后零改造切真接口。

## 4. 模块二：学科知识问答（高完成度科研交互骨架）

路由：`/client/qa`。后端能力引擎尚未接入时，`GET /api/client/modules` 返回 `status = COMING_SOON`。

### 界面与交互设计
- **三段式科研问答布局**：
  - **左栏（历史会话列表，240px，可收起）**：新建问答按钮、示例科研对话列表（以浅标签标明「示例」）。
  - **中栏（学术对话主区）**：
    - 顶部状态条：标明「能力引擎待接入 · 当前展示标准科研问答交互原型，后端接入后自动启用」。
    - 空态引导区：3–4 张经济学典型问题示例卡片（例如「最低工资对就业的实证异质性证据汇总」「货币政策传导机制中的金融加速器文献综述」「DID 方法在产业政策评估中的识别策略演进」），点击可预览标准学术回答结构（结构化结论 + 文内 `[1][2]` 角标 + 因果/实证方法摘要）。
    - 底部多行输入框：附带「检索范围芯片」（当前限定期刊 / 年份 / 仅基于已入库全文）与禁用态「发送」按钮（hover 提示待接入）。
  - **右栏（知识范围与溯源面板，320px，可收起）**：
    - 上半部：检索范围配置预览（复用真实 `GET /api/client/journals` 期刊筛选控件，展示语料底座已就绪）。
    - 下半部：引用溯源卡片槽位（点击示例回答中的角标可高亮对应参考来源片段，展示未来接通后的证据溯源体验）。

## 5. 模块三：论文写作智能体（高完成度科研交互骨架）

路由：`/client/writing`。同样由 `GET /api/client/modules` 驱动接入状态。

### 界面与交互设计
- **双栏科研写作工作台布局**：
  - **左栏（文稿大纲与章节树，220px，可收起）**：
    - 论文项目标题、章节结构树（摘要 / 引言 / 文献综述 / 理论机制与研究假说 / 实证策略 / 结论），支持点击切换预置示例章节与查看字数统计。
  - **中栏（沉浸式学术文稿画布）**：
    - 顶部工具条：文档标题、当前章节、字数统计、「一键转入参考文献自动标注」快捷按钮（**跨模块真打通**：可直接把当前编辑区草稿带入 `/client/citations` 发起真实引文标注！）以及导出占位。
    - 编辑器主体：宽敞的暖白学术纸张编辑区（本地可编辑试写，自动暂存 `localStorage` 不丢草稿）。
  - **右栏（写作智能体协作面板，360px）**：
    - 顶部状态条：「能力引擎待接入 · 预留多步骤写作 Agent 协作协议」。
    - 模式切换标签：`大纲规划` | `段落扩写` | `文献综述` | `润色审校`。
    - 展示标准 Agent 工作流卡片（检索规划 → 证据汇总 → 建议修订 Diff 预览占位）与快捷指令输入框（待接入状态清晰标注）。
