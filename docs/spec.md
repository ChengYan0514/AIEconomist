# AI Economist 管理端规格

首版基线根据仓库现有实现补录。已确认的本轮范围包括论文工作区、系统管理和 AI Economist 品牌更新。系统管理采用单角色模式和独立导出权限，界面沿用选定的浅灰蓝绿 A 版。

已发布并标记为 `ready-for-agent`。[GitHub 规格议题 #1](https://github.com/ChengYan0514/AIEconomist/issues/1)

## 问题陈述（Problem Statement）

论文数据管理员每天需要导入原始文件、追踪解析和全文发布、修复处理失败，以及核对 OpenAlex 关联。首版已经能够执行这些操作，但管理员登录后直接进入论文库，必须在列表、单篇详情和任务结果之间切换，才能知道积压在哪里、某篇论文经过哪些任务，以及某次匹配的候选有何差异。原型和验收标准也缺少一处共同的记录。

首版账号由部署初始化，登录用户共享管理员权限。多人使用时，需要从平台内开通和停用账号，按职责分配权限，追溯权限和数据变更，并在处理失败时辨别问题出在任务本身还是外部依赖。

## 解决方案（Solution）

登录后进入「总览」，可从真实状态计数进入筛选后的论文库，并打开近期任务。论文库保留检索、导入和批量处理，论文详情提供书目、原件、已发布全文、OpenAlex 关联和相应的处理记录。「导入与处理」把 ZIP 预检和运行结果连起来，支持直接筛出失败项并重试。OpenAlex 页面继续负责按出版来源导入元数据，候选复核从对应的匹配任务打开。

品牌统一为 **AI Economist**。导航按数据工作区和系统管理分组。数据工作区包括「总览」「论文库」「导入与处理」「OpenAlex」。系统管理包括「系统状态」「用户管理」「角色管理」「审计日志」，入口按权限显示。全站采用浅色侧栏、无色或低饱和底色和舒展的表格节奏。唯一的主强调色用于主操作、当前导航和焦点，语义状态保留状态文字。

## 用户故事（User Stories）

### 首版基线

1. 作为管理员，我希望登录、退出和修改自己的密码，以便管理工作会话。
2. 作为管理员，我希望按标题、作者、DOI 或论文 ID 检索，并按出版来源、发表年份和全文处理状态筛选，以便定位论文。
3. 作为管理员，我希望按当前筛选导出 CSV，以便在外部核对全部命中记录。
4. 作为管理员，我希望按原论文 ID 查阅历史论文，以便已有记录和链接继续有效。
5. 作为管理员，我希望查看论文的书目、当前原件、处理状态和关联的 OpenAlex 作品 ID，以便了解这篇论文已有的数据。
6. 作为管理员，我希望在历史原件缺失时仍可阅读已有的历史全文，以便继续查阅正文和可用图表。
7. 作为管理员，我希望通过填写出版来源、年份、标题和作者上传单篇 PDF，以便登记新论文。
8. 作为管理员，我希望上传包含 CSV 和原件的 ZIP，并区分可导入、重复和有问题的记录，以便核对批次后再确认。
9. 作为管理员，我希望确认后只导入通过预检的记录，并知道每项的执行结果，以便修正问题文件后重新提交。
10. 作为管理员，我希望编辑书目和替换原件时保留论文 ID，以便继续使用既有引用并处理新原件。
11. 作为管理员，我希望归档暂时不用的论文，并从归档视图恢复，以便调整工作范围和保留数据。
12. 作为管理员，我希望针对所选论文或一个出版来源及年份范围提交处理，以便批量安排工作。
13. 作为管理员，我希望单独发起 PDF 解析，再导入解析产物以发布全文，以便控制全文何时可查阅。
14. 作为管理员，我希望在详情中查阅全文内容块和可用图表，以便核对解析结果。
15. 作为管理员，我希望在任务列表中按类型和状态查找任务，查看摘要、逐项结果和错误原因，以便追踪处理。
16. 作为管理员，我希望在任务结束后重试符合条件的失败项，并可回查原任务，以便从出错阶段恢复。
17. 作为管理员，我希望搜索 OpenAlex 出版来源，按来源和可选年份导入作品元数据，以便为本地论文准备匹配候选。
18. 作为管理员，我希望发起指定论文或范围的 OpenAlex 匹配，并在结果有歧义时确认候选，以便建立准确关联。
19. 作为管理员，我希望历史数据可直接读，新操作保留在新版数据中，以便在共享数据库上接续管理。

20. 作为平台用户，我希望登录后直接看到符合权限的总览，以便定位可以查看或处理的工作。

24. 作为能查阅论文的用户，我希望论文表格清楚展示标题、作者、出版来源、年份、全文处理状态和已关联作品，以便定位目标。

31. 作为数据维护员，我希望暂缓复核时保留待确认状态，稍后回到同一个任务继续处理。
32. 作为数据维护员，我希望确认时看到关联成功、数据变化或作品已关联的反馈，以便核实结果或刷新后重新判断。
33. 作为平台用户，我希望登录、论文工作区和系统管理页都有一致的 AI Economist 标识、布局和操作反馈，以便在不同页面上快速找到操作。
34. 作为使用键盘或窄屏的用户，我希望能定位操作焦点、使用筛选及分页，并可横向查看必要的表格列，以便完整操作。

## 实现决策（Implementation Decisions）

### 延续首版业务规则

- 未登记新版数据的历史论文在列表和详情中仍可读取。对历史论文编辑或处理时按需登记新版数据，保留历史论文 ID、可接续的原件和正文及已有匹配。新版写入使用独立的 `v2_` 表。
- 新论文 ID 使用规范化出版来源、年份、标题和有序作者生成。书目编辑和替换原件沿用既有 ID。导入时按现有规则检查重复论文，归档和恢复只改变可见性。编辑、替换、归档和匹配确认应使用记录版本检测并发变化。
- 单篇导入接受 PDF，ZIP 接受 PDF、XML 和 HTML。预检列出重复和问题记录，确认只提交通过的记录。提交时复核重复；重复确认不会重复入队。需要修正的预检记录重新上传。
- 解析输入使用提交时的原件修订，全文导入使用对应解析产物。在写入前复核原件和解析产物是否变化。全文发布在同一事务写入内容块并切换发布指针。替换原件后，旧全文停止作为当前全文显示。
- 批量处理在提交时确定论文集合。任务表和任务项承载状态、错误与重试关系。重试生成新任务，只处理原任务中符合条件的失败项。活动中的同一论文同一阶段有互斥约束。
- OpenAlex 关联独立于全文处理。匹配在同一出版来源内优先查找 DOI；没有 DOI 命中时用年份、规范化标题和去重排序后的规范化作者姓名比较。唯一候选可自动关联，多候选由管理员确认。只建立作品关联，本地书目继续在论文详情中编辑。

### 数据工作区页面与契约

- 总览使用未归档论文的完整筛选计数。待解析、待导入全文、处理失败和已发布全文分别对应 `UNPROCESSED`、`READY`、`FAILED`、`PUBLISHED`。失败数按论文当前展示状态计算。仍有已发布全文的论文可能同时存在失败任务，因此近期任务另行显示其实际任务结果。计数、过滤结果及导出的筛选条件使用同一口径。
- 登录后默认进入总览，已有论文和任务详情地址继续可用。从总览进入论文库时，链接携带状态，刷新和浏览器返回仍可恢复该入口的筛选。近期任务呈现现有创建时间排序和任务进度。空库、无匹配结果、请求失败和任务等待分别提供反馈，加载失败的计数留空并允许重试。
- 论文库提供一处主导航和一致的导入入口。批量栏明确显示选中数量，发起任务时按当前勾选目标提交；按来源及年份批量处理仍使用显式范围选择。OpenAlex 关联和全文处理用独立表格列与标识。论文表格对未关联记录显示「未关联」，待确认只在能查到对应候选的复核入口展示。
- 论文详情的处理记录按论文 ID 查询已有任务项，展示任务类型、时间、结果及详情链接。沿用已有任务数据，对只有历史状态的论文说明当前查不到新版任务。预检尚未形成正式论文登记的行，仅在已有论文可打开时提供链接。
- 任务详情按任务项状态在服务端先筛选再分页，汇总沿用整个任务的结果。改变筛选返回首屏。全任务的重试资格和范围由现有规则确定，与当前显示的分页无关。ZIP 预检呈现行位序、文件、问题原因及可用的既有论文链接；若当前结果缺少必要字段，先确认新旧任务的显示契约。
- 候选复核从匹配任务的逐项结果打开。本地记录使用当前书目，候选以该次匹配留下的快照展示。管理员暂缓时可以返回任务，状态仍可复核。确认使用打开对照时的论文版本，由服务端重新验证当前候选与作品唯一性。若记录已关联，显示已实际关联的作品。遇到版本或候选变化时提示刷新或重新匹配，管理员重新核对后可再确认。
- 复用现有论文、任务、全文和 OpenAlex 模块。总览先评估复用现有分页总数与任务查询。新增的论文任务记录、任务项状态筛选和结构化预检字段先更新 OpenAPI，按实际查询需要决定是否增加 Flyway 索引或迁移。既有调用方式与旧任务结果继续可读取。
- 完整地址保留给论文详情和任务详情。视觉验收覆盖登录、总览、论文库与详情、ZIP 预检、任务与任务详情、OpenAlex 和候选复核。

### 系统管理页面

| 页面 | 默认视图 | 管理员可以做的事 |
| --- | --- | --- |
| 系统状态 | 被检查的依赖、最近检查时间、状态、简明结果。下方显示有效配置。 | 刷新检查 PostgreSQL、MinerU、新版文件存储、旧版文件存储和 OpenAlex 快照。查看上传上限、任务目标上限和应用版本等安全字段。 |
| 用户管理 | 用户、已分配角色、启停状态、创建时间。支持搜索、筛选和分页。 | 创建账号，编辑显示名称、分配角色、停用、恢复和生成临时密码。 |
| 角色管理 | 角色类型、说明、已分配人数。角色详情含成员和按业务分组的权限清单。 | 创建、编辑自定义角色，查看内置角色，删除无用户关联的自定义角色。保存前显示受影响人数。 |
| 审计日志 | 时间、操作者、动作、对象、结果。支持筛选和分页。 | 打开详情查看经过筛选的变更摘要，在对象可读时转到用户、角色、论文或任务。 |

系统状态的依赖检查各自有超时和结果。数据库验证应用账号能执行必要查询，OpenAlex 验证配置快照的必需表能读取，MinerU 使用健康接口，存储按自身的只读或读写职责验证。页面区分「正常」「不可用」「未检查」，单项故障保留其余检查结果。数据库不可达时，已显示的旧结果标注检查时间，刷新失败显示不可用提示。有效配置只返回指定字段。连接地址、密钥和部署参数由外部部署维护。

### 用户、角色和权限

首期每个账号分配一个角色。内置角色的标识和权限固定。自定义角色由系统管理员从已定义的业务权限中组合。用户管理、角色管理、系统状态及审计日志访问权限保留给内置系统管理员。CSV 导出单独授权。维护人员需要导出时，可分配包含所需维护权限和导出权限的自定义角色。

| 可授权的能力 | 系统管理员 | 数据维护员 | 只读用户 |
| --- | --- | --- | --- |
| 查阅论文、书目及关联 | 是 | 是 | 是 |
| 打开原始文件和已发布全文 | 是 | 是 | 是 |
| 导出论文 CSV | 是 | — | — |
| 导入原件、编辑书目、替换、归档及恢复 | 是 | 是 | — |
| 查阅任务摘要与逐项结果 | 是 | 是 | — |
| 提交解析和全文导入，重试相应处理 | 是 | 是 | — |
| 导入 OpenAlex 元数据、运行匹配和复核候选 | 是 | 是 | — |
| 管理账号与角色、查看系统状态和审计 | 是 | — | — |

- 依赖其他能力的权限在编辑时明确显示。例如原件和全文查阅需要论文读取，发起或重试解析需要任务读取，匹配复核需要论文和任务读取。按任务类型重试时检查该任务对应的执行权限。面向具体使用者的导航、总览和入口使用同一能力集合。
- 账号用户名是历史任务的稳定标识。保持已有 v2 账号和任务引用，迁移时将已有账号接续为系统管理员。新建时设置角色。停用保留账号及历史引用，同时终止已有访问；恢复后重新登录。管理员新建或重置账号时，仅在完成操作后显示一次临时密码，用户需要先设置个人密码再进入工作区。重置和个人改密收回使用旧凭据建立的会话。
- 服务端对请求校验当前账号与权限。已登录但没有权限的业务请求返回 `403`。账号停用后的会话按未登录处理。角色分配与自定义角色权限的变化对变更后的请求生效。已经提交的任务继续按提交时固定的范围和发起人处理。最后一个启用的系统管理员不能被停用或改为其他角色，该约束覆盖并发修改。
- 审计日志记录账户、角色和权限的变更，以及论文导入、编辑、换原件、归档恢复、发布、导出、任务提交和重试及匹配确认。对运行中任务以任务 ID 和逐项结果串联，审核时区分提交与执行。审计事件保留操作者、时间、动作、对象、结果和有限的变更摘要。敏感管理变更与对应成功事件在同一事务提交。日志禁止记录密码、密钥、会话和论文正文，平台只提供读入口。
- 用户、角色、访问控制、审计与业务工作区按用例组织。系统状态复用现有数据库、存储和 MinerU 连接配置。落实时先确定账号兼容迁移、权限和审计的数据库模型、Flyway 迁移及 OpenAPI 契约，再更新实现、测试和现状文档。

### 视觉与交互

- 采用选定的 A 版浅灰蓝绿。使用矿物灰底 `#F4F6F7`、浅灰侧栏 `#F0F3F4`、近白表面 `#FCFDFD`、石墨正文 `#253139`，操作主色参考 `#42696C`。一套侧栏和面包屑覆盖两个工作区。每页以一个主要操作为上限，次要动作使用描边、文字或行尾菜单。
- 默认正文字号 14 px，表格行高参考 48–56 px，双行标题和作者按内容展开。限制粗体的使用，页面标题、筛选、表头和行值各有清晰层级。选中和悬停使用不同的轻量背景；出错、成功和停用同时用文字和视觉标记。
- 正文与背景对比度至少 4.5:1，键盘焦点可见，状态可脱离颜色辨认。窄屏可折叠侧栏并滚动必要表列。视觉走查包括用户列表、角色详情和勾选权限、审计结果与详情、系统依赖单项失败，以及论文列表批量选择状态。

## 测试决策（Testing Decisions）

断言用户可观察的请求结果、处理状态和历史数据边界。后端复用现有 HTTP 集成测试入口，结合隔离 PostgreSQL 与 MinerU 测试服务。前端通过真实浏览器操作已登录管理端，检查路由、筛选、状态反馈和布局。现有论文 ID 单元测试继续覆盖规范化与稳定性。

- HTTP 验收使用混合历史和新版论文，涵盖归档排除、四种计数与筛选一致性、同一论文的任务记录、逐项状态分页、失败项重试、候选并发变化及旧任务结果兼容。沿用现有工作区集成测试的登录、预检、重试、发布和匹配流程作为先例。
- HTTP 验收用已有账号升级及三种内置角色加自定义角色覆盖授权矩阵。重点验证只读用户直接请求写入、导出和管理 API 时被拒绝，停用和重置使旧会话失效，权限变更对已登录用户生效，不能同时撤掉最后两个真正有管理权限的账号。验证历史任务引用、成功审计与变更一致、日志字段脱敏，以及依赖部分失败时仍返回可用结果。
- 浏览器验收走查总览到论文库、ZIP 预检、失败项重试、候选复核及全文查阅。增加新建用户到首次改密、给用户分配自定义角色、从审计查角色变更和从系统状态定位故障的走查。检查键盘、窄屏、加载、无结果和无权限状态，以新确认的原型作为视觉基准。
- 每个新增或变更的业务规则先写预期失败测试。优先断言管理员可观察的计数、页面、结果或错误，以及现有历史数据读写边界。

## 范围之外（Out of Scope）

- 标签、收藏、跨任务统一复核队列、告警和历史监控指标。
- 多租户、组织或团队层级、多角色叠加、论文行级权限、SSO，以及通过页面修改部署参数或密钥。
- 客户端功能、因果图谱、跨系统数据血缘、PDF 批注和重复论文合并。
- 原件与已发布全文并排阅读。正文沿用论文详情的既有阅读流程。
