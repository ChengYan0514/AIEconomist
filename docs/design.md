# AI Economist 管理端首版设计

管理员在论文库查找、导入和整理原始文件，逐步完成解析和全文发布。历史论文直接接续自现有数据库。OpenAlex 元数据导入和匹配是一条可独立发起的工作流。登录页提供管理端登录和客户端入口，客户端显示待开放。

## 用例和业务包

| 业务包 | 管理员能完成的事 | 页面入口 |
| --- | --- | --- |
| 账号 | 登录、退出、修改自己的密码 | 登录页、个人菜单 |
| 论文 | 按书目信息、期刊、年份和处理状态筛选及分页，按当前筛选导出 CSV | 论文库 |
| 论文 | 查阅书目信息、原件、解析状态、已发布全文和匹配结果 | 论文详情 |
| 论文 | 编辑元数据、替换当前原件、归档论文、从归档恢复 | 论文详情、论文库归档视图 |
| 导入 | 上传单篇 PDF，填写来源、年、标题和作者 | 论文库 |
| 导入 | 上传 ZIP，预检 CSV 与包内文件，查看问题行并确认有效记录 | 论文库、导入与处理 |
| 全文 | 为单篇或批量论文发起解析，查看成功或失败结果 | 论文库、论文详情、导入与处理 |
| 全文 | 将已经生成的解析产物导入全文，重试失败阶段 | 论文详情、导入与处理 |
| OpenAlex | 搜索出版来源、启动元数据导入、发起论文匹配并查看结果 | OpenAlex、论文详情 |

侧栏保留「论文库」「导入与处理」「OpenAlex」。论文详情按书目、原件和全文组织，显示下一项可用操作。所有后台工作在「导入与处理」中按类型、状态和时间查询。管理员账号由部署初始化。

外部依赖包括 PostgreSQL、配置的文件存储根目录、项目 Compose 提供的 MinerU 4.1 Tasks HTTP API 和只读 OpenAlex 快照。MinerU 任务和文件 ID 随解析任务保存，重试时可继续查询。解析产物保留逐页结构化内容、Markdown 和同包图片。新版全文从结构化内容导入，历史解析产物继续按旧格式读取。应用入口集中装配服务与适配器。

## 旧库接续

| 旧数据 | 新版用途 |
| --- | --- |
| `original_file`、`original_file_job` | 论文书目、归档信息、当前原件路径、处理状态和已有 Work 关联 |
| `text_file`、`block`、内容块扩展表 | 历史解析登记、正文和图表资源 |
| `source`、`work`、`work_source`、`work_author` | 历史来源名称和匹配候选书目 |
| `dataset_20241125` | 出版来源搜索、来源校验和可选 OpenAlex 元数据导入 |

论文列表合并未登记新版变更的历史论文与新版论文，详情按相同 ID 优先读取新版记录。旧论文在首次编辑、替换、归档或启动处理时按需登记。历史数据接续依靠查询，数据库迁移只建立新版结构。数据库边界见 [ADR 0001](adr/0001-use-existing-paperflow-schema.md)。

## 论文 ID 与导入

采集方提供 `source_id`、`year`、`paper_title`、`authors`。批量输入保留 UTF-8 CSV 约定以及 `file_path`，文件可以使用采集方的原始名称。后端采用旧 `PaperMetadata.fileId` 的 NFKC、空白和大小写规范、字段间换行、有序作者分号分隔，以及 UTF-8 SHA-256 小写十六进制。新版在首次导入时生成 ID，后续始终沿用登记值。

重复导入预检会同时查找新版 ID 和相同书目信息的历史论文。发现重复时返回已有论文并跳过。替换原件是详情页中的单独操作。提交导入时重新验证重复和文件约束，逐行保留成功、跳过和失败结果。归档通过论文可见性控制，恢复后继续使用原论文 ID 和当前原件。

## 拟定的数据库模型

新表都位于 `widi_chengyan`，Flyway 使用独立历史表 `v2_flyway_schema_history`。外键限于新版业务表，读取历史数据按现有 ID 关联。以下为逻辑模型，后续 Flyway 与 OpenAPI 契约同步确定字段类型、约束和接口。

| 表 | 行的含义 | 键与约束 |
| --- | --- | --- |
| `v2_admin` | 一个可登录的管理员 | 管理员 ID、规范化用户名唯一、密码散列 |
| `v2_paper` | 一篇新论文或一篇有新版数据的历史论文 | 论文 ID 主键。记录来源、年份、标题、有序作者、DOI、历史标记、当前原件位置、修订号、归档时间、当前匹配和已发布全文引用。 |
| `v2_parse_artifact` | 某一原件版本成功生成的一份解析产物 | 解析产物 ID 主键。记录论文 ID、原件版本、JSON 和 Markdown 等已登记的存储位置。 |
| `v2_content_block` | 一个已导入的有序内容块 | `(解析产物 ID, 块序号)` 主键。记录块类型、正文、页码和定位坐标，图表与其他类型的专有属性随块存储。 |
| `v2_openalex_work` | 从某一出版来源导入的一条 OpenAlex 作品元数据 | `(source_id, work_id)` 主键。保存标题、年份、DOI 和作者，索引覆盖按来源查 DOI 或年份。 |
| `v2_job` | 一次导入、解析、全文导入或匹配操作 | 任务 ID 主键。记录类型、输入范围、操作人、状态、创建和结束时间及错误摘要。 |
| `v2_job_item` | 一次操作中的一行输入或一篇论文结果 | `(任务 ID, 项序号)` 主键。记录目标、输入原件版本、状态和错误，同一论文同一阶段至多一个活动项。 |

同一阶段失败只重试失败项。在任务提交时固定输入，执行时复核论文可见性和原件版本。每篇全文导入在一个事务中写入其内容块并切换当前发布引用。原件替换和归档都保留历史文件和全文。原件替换后，直到新版本完成全文导入，页面显示当前版本的待处理状态。同一原件重解析时，先前可读的全文可保留到新解析结果成功发布。

## 首版验收规则

- 批量处理按勾选论文或一个期刊和年份范围提交，提交时固定论文集合。
- OpenAlex 按期刊和可选年份导入。在同一出版来源内，优先匹配唯一 DOI，其次尝试唯一的精确书目候选。有歧义时保留待确认结果，由管理员挑选。
- 以只读方式读取历史文件目录，使用单独目录存储新版原件和解析产物。旧文件缺失时显示缺失状态，历史正文从数据库照常读取。
- 原型用真实库和历史目录验证查阅链路，用隔离测试环境验证写入、ZIP 预检、原件替换、MinerU 解析和失败重试。
